      📘 How to read this page (click to expand)

      What this is: the router decides — on every bar — which strategy should fire for which symbol, based on the current market regime and each strategy's historical win rate in that regime. It runs automatically by default when the bot starts; set ROUTER_ENABLED=false only if you want single-symbol mode.

      Current Regime by Symbol (cards):
      • Each card shows one symbol and its current regime tag (computed fresh on every refresh).
      • Tag format: trend:vol:gap:orbQ — e.g. trend-up:high-vol:gap-up.
      • Colored chips break out the parts: trend-up / trend-down / high-vol / low-vol / gap-up / gap-down.
      • If you see unknown or empty chips, the bot doesn't have enough recent bars to classify yet (needs ~25 bars).
      Win-Rate Heatmap (table):
      • Rows = active strategies. Columns = regime tags seen in trade history.
      • Each cell shows win rate on top and sample size below (n=15 means 15 trades in that bucket).
      • Green ≥ 65% win rate · amber ≥ 50% · red < 50% · dash = no data.
      • Sample sizes < 10 are noisy — the router still uses them but weights them down with a √(n/30) confidence multiplier.
      • The router picks the strategy with the highest score in the symbol's current regime column. Score = winRate × √(min(samples,30)/30) × diversification multiplier.
      What the buttons do:
      • Bootstrap from Backtest — runs every active strategy across every watchlist symbol on recent data. Populates the heatmap so the router has stats to work with. Run this first.
      • Year Backtest (Options) — heavier version: ~1 year of 5-min bars in options mode. Pulls live IV/DTE from Alpaca per symbol. Adds ~1-3 min runtime but gives you more samples per regime bucket.
      • Optimize All by Regime — for each (strategy × regime) bucket with ≥ 10 historical trades, runs Hermes to tune the strategy's params separately for that bucket. Stored under byRegime[tag].params in learned-params.json.
      • Refresh — re-classifies regimes and re-fetches the heatmap. Click after the bot has been running for a while to see updated stats.
      Recommended workflow:
      1. Click Bootstrap from Backtest (or Year Backtest for more data).
      2. Look at the heatmap — find which strategies have green cells in many regimes.
      3. Open the Strategies & Backtest tab → click Validate (CPCV) on each candidate. Only trust strategies that come back ROBUST or OK. LIKELY_OVERFIT = don't trade.
      4. Set ACTIVE_STRATEGIES env var to just the validated survivors (e.g. hybrid10,vwap-reclaim).
      5. Click Optimize All by Regime to tune surviving strategies per bucket.
      6. Router starts on by default. To disable it, set ROUTER_ENABLED=false; otherwise restart the bot service and watch the logs.
      Live decision log format (in Railway → bot-stream logs): 
      [Router] QQQ trend-up:high-vol → hybrid10 chosen: 73% win rate (22 samples, regime) · beat vwap-reclaim (51%)
      • source: "regime" = the router used a regime-specific win rate.
      • source: "global" = fell back to that strategy's overall win rate because no per-regime data yet.
      • source: "prior" = no data at all, used a neutral 0.5 prior with low confidence.
      • diversification ×0.8 = strategy was already used today on another symbol, score discounted to spread risk.
      The router classifies each symbol's regime, scores every active strategy by historical win rate in that regime, and picks the top-scoring entry. Diversification penalty applied to strategies already used today.

      📘 What is the Screener? (click to expand)

      The 4th brain. A supervised XGBoost model (not an LLM) predicts each symbol's forward return from its recent price action and turns it into a concrete price target, horizon, and confidence. This screener runs it across your entire watchlist and ranks the names it likes — purely advisory, it never places an order.

      • Bias — model direction (LONG/SHORT) for the forecast horizon.
      • Target — predicted price = current × (1 + expected return).
      • Conf — model conviction (0–100%). The router only acts on picks above PREDICTOR_MIN_CONFIDENCE.
      • Signal — which strategy signals are firing right now; ✓ means a signal agrees with the model.
      • Source — xgboost once you've trained a model, otherwise heuristic baseline. See ml/README.md to train.

      📘 How to use this page (click to expand)

      Two modes of backtesting:

      • Single Run — pick one (strategy × symbol) combo, run it on options data over your chosen window, see the equity curve and full trade list.
      • Bulk Run — run every active strategy against every watchlist symbol in options mode. Each cell of the summary shows win rate, total options P&L, and total premium moved per (strategy × symbol).

      IV/DTE source:

      • Live (default) — pulls today's IV and nearest expiry DTE from Alpaca per symbol. Most realistic for current conditions.
      • Static — uses your hand-entered IV % and DTE. Useful for stress-testing strategies under specific vol environments.

      Options-specific metrics (in addition to standard stock metrics):

      • Total P&L = sum of all per-contract option PnL (gross, before commissions)
      • Total Premium Moved = total dollars of option premium that changed hands (entry + exit combined)
      • Avg Premium = average entry premium per share — useful for sizing intuition
      • Win Rate here is on the option PnL, not the underlying stock direction (an in-the-money option that decays from theta still loses)
